## v0.7.1（2026-11-10）benefit 环境 404 修复

- [x] 修复新窗口对话必报 `InferHub.APIG.0101.404 The API does not exist or has not been published in the environment` 的问题
- [x] 根因（A/B 实测）：`maas_type: benefit` 头把请求路由到「免费权益环境」，权益环境未部署的模型（如 glm-5.3-flash）在该环境不存在对应 API；去掉该头立即恢复
- [x] 该错误以 **HTTP 200 + SSE 内嵌事件**返回（非 4004.200、非 HTTP 404），原有 benefit 降级（只认 `InferHub.4004.200`）永远不触发 → 新增 `BENEFIT_ENV_CODES`（`APIG.0101` / "does not exist or has not been published"），在 `mapHttpError` 与 `parseSse` 两处识别后复用既有降级路径：去头重试 + `markNoBenefit` 记忆（每个模型最多多花一次往返）
- [x] 回退上一轮误加的 `Agent-Type: INFERHUB_AGENT` 对话请求头（实测与路由无关）
- [x] 验证：离线单测（0101.404 → 去头重试 → 成功）、真实网关端到端（正文 / finish / usage 正常）均通过；A/B 对照探针见工作区 `wb-diag/probe-benefit-ab.mjs`

## v0.9.1（2026-11-25）上下文压缩 / 模型切换兼容修复

- [x] 修复已有会话切换到 `wbai/hy4flash`、`wbai/hy4flash-free` 等模型时报 `MODEL_SWITCH_COMPACTION_FAILED: this.adapters.get(...)?.adapter.imageRequestPricing is not a function`
- [x] 根因：适配器声明了 `inputModalities: ['text', 'image']`，却没实现宿主 token 计量每次测量都要调用的同步方法 `imageRequestPricing()`；可选链 `?.` 只挡「适配器不存在」，挡不住「方法不存在」，于是上下文压缩阶段抛 TypeError，模型切换被回滚
- [x] 新增共享模块 `lib/image-pricing.js`：`priceImages()` 给每张图 1024 token 的中性估算（offload 的图记 0 并留 `[image omitted]`），不声称是厂商真实消耗
- [x] `WorkBuddyAdapter` 与 `CodeArtsAdapter` 均补上同步 `imageRequestPricing(provider, model)`；两个渠道的视觉模型都不再因缺方法卡住压缩
- [x] 验证：计价对象结构、`wbai` / `devcloud` 两个适配器经注册路径拿到的实例都能通过宿主契约调用——全部通过
