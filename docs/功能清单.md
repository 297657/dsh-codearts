# 功能清单（版本沿革）

本插件围绕「多渠道免费积分的自动领取与可视化治理」逐步演进，按版本列出功能点。
协议细节与踩坑记录见根目录 [MEMORY.md](../MEMORY.md)。

## v0.1 – v0.2（2026-11 前）

- [x] 三渠道每日签到：`buddy`（CodeBuddy 中国版）/ `workbuddy` / `codearts`（华为云）
- [x] 启动后 15s 自动跑一轮（`DSH_CODEARTS_AUTO_CHECKIN_DELAY_MS` 可调）
- [x] 结果挂 `/api/codearts-checkin`，只做签到，不注册 LLM 适配器、不改凭据

## v0.3.0（2026-11-04）浏览器半身

- [x] 新增 `client.js`：设置页注册「签到」页（排在 WorkBuddy 之后）
- [x] 展示三渠道每个账号的签到状态与额度
- [x] 「立即签到」「刷新」按钮

## v0.4.0（2026-11-04）账号管理

- [x] 设置页内账号清单：新增 / 删除 / 启用停用
- [x] CodeBuddy 扫码登录（`lib/buddy-login.js`）
- [x] 多账号池（`orderPool` 轮转），签到覆盖所有账号

## v0.5.0（2026-11-04）CodeArts 页面内登录

- [x] CodeArts AK/SK 登录入口，token 自动刷新
- [x] ⚠️ 确认 refresh_token 为一次性：刷新即作废，跨设备共用会互踢

## v0.6.0（2026-11-04）模型渠道

- [x] 注册 `devcloud/*` provider，DSH 对话可直走 CodeArts 模型
- [x] 额度为积分制；并发会话上限 3（按账号）
- [x] 模型清单以服务端为准，动态拉取

## v0.6.1（2026-11-04）DSML 工具通道

- [x] DSML 工具调用协议支持（`lib/dsml.js`）
- [x] 并发上限实测修正与排队等待计划（`QUEUE_WAIT_PLAN_MS`，默认 3/9/20 秒）

## v0.6.2（2026-11-04）会话治理 + 剩余积分

- [x] 排队状态查询（`/api/v1/queue/status?task_id=`）

- [x] 主动终止会话（abort 前先置 `phase='aborting'`，异常路径断流防「越用越卡」）
- [x] 终止后 45s 冷却（服务端无会话列表/关闭接口的补偿方案）
- [x] 会话界面显示剩余积分（`statistics/plugin` 的 `metrics`）

## v0.6.3（2026-11-04）重复账号判重

- [x] 身份解析（`lib/identity.js`）：refresh_token JWT → `account_id`
- [x] 账号池按 `identityKey` 去重（AK/SK 不同但同一账号只算一个）
- [x] 重复账号标记（`lib/duplicates.js`）

## v0.6.4（2026-11-04）首屏性能 + 全渠道余额

- [x] 状态缓存 + 有界并发探测（`mapLimit`），首屏加载显著提速

## v0.6.5（2026-11-06）提示误导修复

## v0.7.0（2026-11-09）WorkBuddy 模型渠道

- [x] WorkBuddy 在线模型接入为 `wbai/*` provider（别名避开 OFM 的渠道黑名单：`workbuddy|codebuddy|codearts|huawei…`）
- [x] 自包含实现：`lib/wbipc-client.js`（命名管道 + HMAC 握手）+ `lib/workbuddy-llm.js`（模型目录、分段续写、SSE 解析、11128 指纹改写）
- [x] 走本机 wbipc：直连 HTTPS 会被渠道校验拒（11128 request illegal）
- [x] 分段续写：宿主 http.fetch 有 640KB / 50s 两条硬限制，单次拿不到长回答
- [x] 设置页显示模型渠道状态（桌面端是否在跑、读到的模型数）
- [x] `/api/codearts-checkin/workbuddy`、`/workbuddy/refresh` 观测接口
- [x] 桌面端未运行时该渠道不进选择器（避免「点了必失败」），签到完全不受影响

## v0.7.1（2026-11-10）benefit 环境 404 修复

- [x] 修复新窗口对话必报 `InferHub.APIG.0101.404 The API does not exist or has not been published in the environment` 的问题
- [x] 根因（A/B 实测）：`maas_type: benefit` 头把请求路由到「免费权益环境」，权益环境未部署的模型（如 glm-5.3-flash）在该环境不存在对应 API；去掉该头立即恢复
- [x] 该错误以 **HTTP 200 + SSE 内嵌事件**返回（非 4004.200、非 HTTP 404），原有 benefit 降级（只认 `InferHub.4004.200`）永远不触发 → 新增 `BENEFIT_ENV_CODES`（`APIG.0101` / "does not exist or has not been published"），在 `mapHttpError` 与 `parseSse` 两处识别后复用既有降级路径：去头重试 + `markNoBenefit` 记忆（每个模型最多多花一次往返）
- [x] 回退上一轮误加的 `Agent-Type: INFERHUB_AGENT` 对话请求头（实测与路由无关）
- [x] 验证：离线单测（0101.404 → 去头重试 → 成功）、真实网关端到端（正文 / finish / usage 正常）均通过；A/B 对照探针见工作区 `wb-diag/probe-benefit-ab.mjs`
